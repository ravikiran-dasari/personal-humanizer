# Contributing

Keep changes focused on the skill, its evidence, or its maintenance documentation. Preserve the distinction between observed preferences, hypotheses, and provisional defaults.

Before opening a pull request:

1. Read the applicable guidance in `docs/skill-development/`.
2. Keep the skill's core instructions concise and load optional references only when needed.
3. Check that frontmatter is valid, the skill name matches its directory, and every relative link resolves.
4. Run relevant cases from `.github/skills/personal-humanizer/references/validation-cases.md` and record any limitations; evaluation is manual at present.
5. Review the diff for accidental personal data, generated files, or unrelated changes.

When changing style guidance, update the supporting evidence and explain whether a rule is observed, inferred, or provisional. Do not treat AI-assisted samples as direct evidence of the writer's voice.
